# Harnesses

Codemux supports the adapters below; run `codemux --version` to identify an installed release. An adapter's minimum version and audited ceiling are code-enforced declarations. An installed version or successful live probe is separate evidence; neither silently changes that declaration.

Every adapter accepts the four autonomy levels. Scode is required below high and at every level on Qwen's legacy fallback. An unsupported hermetic, tools-none, result-json, spend-limit, or provider-override request is refused before launch.

`--effort none` is the CLI's "send no effort flag" spelling on every adapter: a harness whose effort list has no native `none` launches with no effort flag, and the adapters that carry a native `none` (aider, cline, codex, copilot, droid, goose, kimi, opencode, pi, qwen) send their own mapping of it. Other values outside a row are refused. Qwen's legacy `qwen-coder` fallback has no model selection and requires scode even at high autonomy. [Isolation](isolation.md) defines the tool exceptions and clean-directory requirements. [Result envelopes](results-and-usage.md) describe the structured adapters (every adapter whose Result JSON cell says yes). [Provider overrides](provider-overrides.md) cover endpoint and token-limit constraints.

Claude and Z.AI use Claude Code's native `--max-budget-usd` flag on headless runs. It is a soft threshold against Claude Code's estimate at Anthropic prices; the final response may exceed it, and Z.AI's estimate is not provider billing. A stopped run fails through its native error result. Pi uses an explicit extension to enforce a soft cap on verified native USD estimates. Missing prices, provider overrides without USD rates, native compaction, and requested branch summaries stop the run before unaccounted requests; compaction retries do not expose every request's cost.

Hermetic sessions exist on agy, aider, claude, cline, codex, copilot, droid, goose, gemini, kimi, opencode, openhands, pi, qwen, and zai (`codemux session --hermetic`; see [sessions](sessions.md#hermetic-sessions)); codex and kimi each run in a per-session private home that persists across turns and `--resume`, loads no operator config, instructions, skills, hooks, or agents, and is removed by `--final` or the stale sweep. Codex (audited 0.166.0): startup config suppresses account extensions and thread config reapplies document/tool policy on fresh and resumed threads. Project-settings sessions retain repository documents and hooks through private native trust configuration. Writable tools-none sessions use a sanitized local model catalog for the full app-server lifetime without changing model/provider selection; they require a cached model descriptor and a sandbox-readable state directory. The executable and catalog are revalidated before spawn. Workspace rules remain the caller's policy channel; app-server has no exec-style ignore-rules flag. Kimi (audited 2.5.2): every turn spawns under the run path's env prefix over the private HOME and KIMI_CODE_HOME with an empty private `--skills-dir`, and the private brand home's config.toml is generated once, at the first turn of a fresh home, from the operator's allowlisted config; a config the caller placed there first joins the merge, its `[[permission.rules]]` kept whole. A fresh tools-none session can bind a `tools: []` profile through `--agent-file`; native resume restores that allowlist without repeating the creation-only flag. The driver verifies the stored tool policy before resume.

## Version enforcement

Before launch, codemux resolves and trust-checks the executable, probes its version with a sanitized environment, and checks its file identity to detect replacement between probe and launch.

- Below minimum: refuse. A semver prerelease orders below its own release, so `1.18.10-beta.1` is below a `1.18.10` minimum; the probe reads and compares the full version including the suffix.
- Minimum through audited ceiling: proceed without a version warning.
- Above audited ceiling: warn and proceed unless a known incompatible change applies.
- Unknown version: warn for ordinary contracts; Copilot refuses because its contract requires `--binary-version`.
- No contract entry: no version check for that harness.
- `CODEMUX_ALLOW_UNTESTED_HARNESS=1`: explicitly downgrade version refusals to warnings. It does not provide missing enforcement.

OpenCode 1.18.18 and later have a recorded permission change: `--agent build` alone no longer gates writes or execution. Low/medium unsandboxed launches are refused by the compatibility rule; scode mitigates that filesystem boundary. Session transports can require higher floors than one-shot runs; see [sessions](sessions.md).

Experiment MCP has a separate version floor: Claude/Z.AI require Claude Code 2.1.280 or later, Codex requires CLI 0.165.0 or later, and Kimi requires Code 2.3.2 or later. Codex requires the spec's `codex-wall-time` opt-in, explicit `-m`, and a populated real model cache; a cache whose `client_version` differs from the detected client version is served with a stderr warning and a `catalog_client_version_mismatch` record ([experiment MCP](experiment-mcp.md)). Every Codex experiment serves a sanitized catalog, including direct, omitted, and null tool modes: for every served model, Codemux deletes `tool_mode` and `multi_agent_version`, removes only `clock` from `experimental_supported_tools`, and sets `apply_patch_tool_type` to null. The preserved `gpt-6-astra` run at 02:13 on October 29, 2026 verified backend acceptance and direct tool delivery. See the [catalog evidence](experiment-codex-catalog.md#rollout-evidence-and-correlation). Experiment flags still disable `code_mode` and `code_mode_host`, and foreign function or custom `exec` calls fail with `unknown_tool`. Kimi requires `kimi-wall-time`; Codemux reconstructs its provider content from wire records using the 2.3.2 renderer. Codex and Kimi use an authenticated loopback MCP relay. Kimi's tools-none experiment profile permits only the experiment MCP namespace. Live probes on October 29, 2026 confirmed Kimi's projected header and Codex's `exec` code-mode call. These experiment floors do not change the ordinary-run declarations above. See [experiment MCP](experiment-mcp.md).

Version checks matter beyond scode. Scode controls filesystem/network access, while native policies control tool exposure, approval, prompt discovery, transport framing, and result interpretation. A working sandbox does not verify those semantics.

OpenCode experiment MCP requires 1.19.5. Run and paired check use a private observer plugin and authenticated loopback relay. Final provider requests must preserve the tool inventory, call IDs, arguments, and text results; unsupported media or changed results fail verification. Ordinary runs retain pure mode and report no served model. These new launcher paths are verified with synthetic executables, not a live provider.

## Harness selection and prompt transport

The parity gate requires `sessions(permissions)` or `sessions(no-permissions)` labels and JSON fields `capabilities.sessionPermissions` and `sessionPermissionsNote`, derived from `SESSION_AGENTS`.

Use `codemux list` for discovery, `codemux doctor` for local configuration diagnostics, and `codemux verify --show-scode` for static command previews. `list` marks each agent with its capability labels (`model`, `autonomy`, `effort`, `hermetic`, `tools`, `provider`, `result-json`, `budget`, `sessions`; `model(run)` and `effort(run)` would mark a harness whose TUI takes no `-m` or no `--effort`; every current adapter carries both in TUI, so neither qualifier prints); `doctor` prints the same capabilities per installed harness plus a version-contract verdict — ok, above the audited ceiling, below the minimum, a known break at named autonomy levels from a recorded version, no contract, `untrusted binary (<reason>)` (the probe refused a binary that fails the launch trust check), or unreadable (possibly timed out) — from the same local version probe the launch gate uses, with no model request. A preview does not authenticate or prove model behavior. `codemux check` sends a real request and spends quota.

Cursor resolves the explicit `CODEMUX_CURSOR_ENTRY=cursor` opt-in first, then `cursor-agent`, then `agent`. Pass the opt-in with `--pass-env CODEMUX_CURSOR_ENTRY`. The desktop wrapper can install or update the standalone agent; codemux does not invoke it automatically. Its version probe is `cursor agent --version`, not the desktop app's version.

Antigravity's accepted `--effort` values depend on the model: the binary's help lists `low`, `medium`, `high`, `xhigh`, and `max`, and codemux accepts those five, but a model such as `gemini-4-argon` takes `low`, `medium`, and `high` only and fails after the spawn on the others (live matrix, 2026-11-07). A model name that ends in an effort suffix (`gemini-3.8-flash-low`) already carries its effort, and codemux refuses `--effort` beside it.

Antigravity binds its prompt as `--print=<prompt>` and uses equals forms for enum flags. **The prompt reaches process argv even when codemux reads it from `-f` or stdin.** Kimi also uses argv prompt transport. Codemux avoids printing those prompts, but input-file or stdin selection cannot hide them from process inspection when the upstream interface requires argv.

## Headless reply output

OpenHands without stored settings prints "Headless mode requires existing settings." and exits 0 without running the task. Codemux reports that run as failed: exit 1, a diagnostic on stderr, and `success: false` in the result envelope (live matrix, 2026-11-07). Run `openhands` once to configure it.

Kimi's headless bullet format was observed on 2.3.2: each reply block starts with a `• ` prefix, and continuation lines use two spaces. When the installed version probe reports major version 2 or higher and all stdout follows this format, codemux removes those prefixes and indents, joins blocks with one blank line, and ends the reply with one newline. For example, `• A\n  B\n\n` becomes `A\nB\n`. Versions 0.x and 1.x and unknown versions keep their output unchanged. Plain replies and other output stay unchanged. Stderr stays unchanged.

Kimi hermetic runs use private HOME/KIMI_CODE_HOME directories, a filtered config, an empty skill directory, and an explicit agent file. Project customization paths are refused; see [isolation](isolation.md). Result-json runs use stream JSON plus the session wire log for usage; see [results](results-and-usage.md). These mechanisms are grounded in 2.3.2 source and verified with synthetic fixtures. No new live check is claimed.

An October 29, 2026 comparison against Kimi 2.4.0 retains the experiment floor at 2.3.2: the reproduced result rendering and wire evidence remain equivalent. `run-v2-print.ts` changes telemetry, Plan mode, and workspace leases; `loopService.ts` adds logging and a warning watchdog. The MCP connection manager adds liveness probing and reconnect handling. Codemux's relay answers pings locally and replays the cached successful initialize result without clearing held tool calls. Every recording now includes `t`; existing event timestamps are preserved. See [the source line ranges](experiment-mcp.md#kimi-configuration-and-delivery-evidence) and [recording schema](experiment-mcp.md#normalized-records). The fresh live 2.4.0 `hold:400000` probe with these fixes remains pending.

## TUI restrictions

All adapters provide an interactive entry point, but headless options do not automatically apply there. Hermetic mode, tools selection, result envelopes, and experiment MCP injection are not TUI options. The one hermetic carry-over is structural: every Claude and Z.AI TUI launch passes `--safe-mode`, the customization-off baseline of a hermetic run (first row below).

The Playwright MCP option is the one launch that keeps the user settings source instead. |
