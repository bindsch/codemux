# Panel review by zai

**Verdict: READY WITH CHANGES**
Review basis: the design doc, the codemux source listed in the brief, and the three repo docs. The Prompt B brief itself (`<workspace>/lab-service/docs/codemux-live-session-prompts.md`) is permission-denied in this session — the same denial the design records in its §8 — so plan findings below are against §7 as written, and the §4.1–4.2 message vocabulary still needs reconciling with Prompt B before code. Claude Code 2.1.280, codex-cli 0.159.3, agy 1.2.14 per the design's own evidence.
## 1. Defects in the design
- **major — §4.7 contradicts itself on the scode-wrapped codex parameter shape.** `docs/LIVE-SESSIONS-DESIGN.md:495-499` says every thread/turn start carries sandbox and approval parameters "derived exactly as `run` derives `-s` and `-c approval_policy=…`", then says a scode-wrapped session "passes the bypass `run` uses" — but `run` derives *neither* when sandboxed (`src/adapters/codex.ts:227-229` pushes `--dangerously-bypass-approvals-and-sandbox` and skips `mapAutonomy` entirely), and step 2's grammar test ("both parameters present… from the `--auto` mapping", design:733-736, 747-748) would fail on the bypass shape. An implementer taking the first reading gives every sandboxed codex session a *nested* native sandbox under scode, violating `docs/HARNESS-COMPATIBILITY.md:212-214`. Fix: state one rule — parameters are always explicit, but scode-wrapped sessions carry the bypass pair (`danger-full-access` + `never`) at every level, and the mapping's pair applies only to the unsandboxed high-only shape (which is the same pair anyway).
- **major — the session runner is never reconciled with the launch/process-runner machinery it must replace.** `src/launch.ts:26` makes `launchRunRequest` "the ONLY place a run is spawned", and its capture path cannot host a session: `runCapturedCommand` writes stdin once and closes it (`src/process-runner.ts:231-234`), caps output at 16 MiB (`src/process-runner.ts:13,86-92` — a hours-long stream dies at exit 125), and force-kills 2 s after a signal (`src/process-runner.ts:17`) against the design's 10 s `--shutdown-grace`. Fix: add a §4.7 paragraph naming the session runner as a peer spawn path — incremental stdin, no cumulative capture cap, its own signal/grace/exit-143 semantics — and say explicitly that `run`'s path is untouched.
- **major — the no-adapter-state invariant is not carried over.** Adapters are singletons and per-run state must live in a launcher-owned context (`src/adapters/base.ts:43-47`, `:52-65`); §7 step 1 (design:698-701) never says where per-session state (pending control requests, FSM, seq counter, registry handle) lives, and the obvious implementation — fields on `ClaudeAdapter`/`CodexAdapter` — would let two concurrent sessions through one broker cross-talk. Fix: one sentence in step 1: all session state lives in a per-session context; adapters gain only pure builders (a `buildSessionCommand` peer of `buildRunCommand`).
- **minor — fail-closed is specified for codex but not for claude.** §6 item 2 (design:677-679) demands loud failure on unknown app-server shapes, but nothing says what a claude session does with an unknown stream-json `type` or a malformed stdout line; the repo invariant (see `src/result-envelope.ts:366-374`) refuses drift rather than dropping it. Fix: state that unknown claude events are a fatal `error` (source `harness`) ending the session, never a quiet skip.
- **minor — behavior for capability-false inputs is undefined.** §4.1 (design:222-227) defines `user`-during-turn, `steer`, and `interrupt` only for the true cases; with agy shipping in v1 (§10) and `steer`/`interrupt`/`user_during_turn` all false (§3.4, design:195-201), the design never says whether such inputs are `input_rejected` (and with what reason) or buffered. Fix: enumerate the rejections for each false capability.
- **minor — resumed-session identity and concurrent resume are unspecified.** §4.5 (design:398-412) never says whether a resumed claude session reports the same `session_id`, whether resume writes a new registry entry, or what happens when two `codemux session --resume <same-id>` run concurrently (both transcripts under one home). Fix: specify same-id continuation, one entry updated in place, and either refuse a resume of a not-`ended` entry with a staleness rule or document concurrent resume as allowed.
- **minor — the medium Edit ceiling predicate must reuse `grantRule`, not reimplement it.** §4.1 (design:255-259) says edits "on paths inside the `grantRule` launch-directory scope", but the scope's canonicalization (realpath, NFC, grammar refusals) is subtle and already encoded at `src/claude-autonomy.ts:33-71`; a second implementation will disagree with the grant the harness actually enforces. Fix: name `grantRule` as the one code path the predicate calls.
- **minor — sandboxed claude sessions will outlive their credential mirror.** The mirror is refreshed only at `prepareSandbox` launch time (`src/adapters/claude.ts:57-94`) and the sandboxed child cannot reach the Keychain; a hours-long session hits a rotated token mid-session with no refresh path. Fix: document mid-session auth failure as a session-ending (resumable) error, or add a refresh hook.
- **minor — `--timeout` bounds are unstated.** §4.5 (design:424-427) defaults to none, but `run`'s validation caps at 86 400 s (`src/cli-runtime.ts:266-274`, `src/process-runner.ts:15`); say whether the 24 h ceiling applies to sessions or is consciously raised.
- **minor — `raw` fidelity is ambiguous.** "The verbatim parsed harness event" (design:309-311) — parsed-then-reencoded objects lose key order, duplicate keys, and original framing; for an archival channel this should be pinned. Fix: define `raw` as the harness's original line (string) or the parsed value, and which one the broker archives.
- **minor — step 4's agy conditional contradicts the approval.** Step 4 says agy ships "only if Laurent wants it in v1" (design:773-774) while §10 records that he approved it for v1 (design:966-967). Fix: delete the conditional.
- **minor — the FSM models one pending permission and ignores its shutdown interaction.** `turn_active ⇄ awaiting_permission` (design:699-701) reads as a single pending request (claude can have parallel tool calls), and §4.6 (design:448-454) never says a pending request is answered deny or abandoned when shutdown/interrupt/turn-timeout fires while the turn is blocked on the host. Fix: model pending requests as a set and specify deny-on-shutdown.
## 2. Security
- **major — nothing obliges the session spawn to run the validation seams that make "codemux executes only what it validated" true.** Steps 1–2 (design:698-744) hand-roll spawns (a fake-harness CLI path, a JSON-RPC client over child stdio) without mentioning `resolveExecutionCommand`/`resolveTrustedCommand` (`src/adapters/base.ts:172-186`), `buildExecutionEnv`/`sanitizeEnvironment` (`src/environment.ts:249-276`), or the pre-launch version gate `assertHarnessSupported` (`src/cli-runtime.ts:428-491`) — a session that skips any of them runs a PATH-planted harness, a stray env var, or an unaudited version for hours. Fix: list these as mandatory seams for the session runner (version gate included) in §7 steps 1–2, plus `beforeLaunch`/`prepareSandbox` equivalents (zai's API-key check, claude's Keychain sync).
- **major — §4.8's writable-set premise is false, so the placement rules are over-claimed.** Rule 2 checks "the writable set codemux itself hands scode (it constructs that set, so it knows it)" (design:575-577), but codemux hands scode only `-C`, `--trust`, and `--ro/--rw` (`src/sandbox.ts:26-63`) — the deny rules are scode's presets, not constructible from codemux; and a sandboxed *low* or *high* child (unscoped Write/Bash, or caller-approved anything) can write `~/Library/Application Support/codemux/live-sessions.json` from any cwd, so "the placement rules… make the guards hold against the sandboxed session child" (design:567-569) holds only for read-only/medium children. Fix: define the check as the union codemux can compute (cwd, `--add-dir`s, harness home) and state plainly that low/high sandboxed children remain registry writers, bounded by the same re-derivation residual §4.8 already accepts.
- **minor — symlink traversal from a writable cwd reaches the registry and is inside the residual but unsaid.** A cwd-resident symlink (`repo/link -> ~`) lets a medium child's Edit write through the link to the registry while rule 2's lexical check passes (design:573-582); the re-derivation frame already covers it, so say so in one sentence rather than leaving round 3's class half-documented.
- **minor — no framing-level line cap.** `text` is bounded at 16 MiB (design:229-231) but an unterminated input line can grow without bound before any field is parsed; cap the input line (e.g. 17 MiB) and define overflow as rejection-plus-resync or connection drop.
- **minor — the `--event-log` tee, if it ever ships, inherits registry obligations.** A crash-forensics tee (design:660-662) is codemux-written state a sandboxed child could forge or read; it needs the same placement-and-trust analysis as the registry before it becomes a commitment.
## 3. The plan (§7)
- **major — the risk the design says to kill first is probed sixth.** §6 item 3 (design:681-684) says the scode bidirectional-stdio probe "exists to kill this risk first", yet it runs as probe 6 after the whole session core is built (design:725-729); hoist it to a step-0 standalone check (an echo/relay loop under scode — zero quota) before step 1 begins.
- **major — step 1 is too large for one reviewed commit.** It bundles framing, envelope, input dispatch, the FSM, the CLI with full run-flag parity, the claude spawn, seven parsers, the control-response writer, the entire autonomy ceiling, ~8 test classes, and seven live probes (design:698-729); split into (1a) framing+FSM behind the fake harness, (1b) claude wiring and parsers, (1c) the ceiling and its tests, probes interleaved where they gate the next slice.
- **major — step 1 creates a working, unguarded `--resume` two steps before the guards exist.** Probe 7 exercises shutdown-and-resume (design:729) while the registry, its cross-agent/home/containment/reach refusals, and exit 66/78 land only in step 3 (design:750) — every commit in between reintroduces the round-17 replay hazard if the branch is merged or cherry-picked mid-way; reorder (registry before the codex adapter) or make step 1's `--resume` fail closed with the probe run behind a test-only seam.
- **major — no probe pins the app-server shapes the design itself tags `[verify]`.** §3.2 (design:110-121) marks param shapes unverified, and probes 8–9 cover only `CODEX_HOME` relocation and daemon isolation (design:744); add a live probe recording a full `initialize → thread/start → turn/start → item/* → turn/completed` exchange (framing included — LSP-style headers vs NDJSON is unpinned) plus the server→client request surface beyond approvals, before the client is written.
- **minor — missing tests the plan should require.** Framing edges (malformed line, unknown input type, NUL, 16 MiB boundary, oversized line); pending-permission × shutdown/`--turn-timeout` interaction; codex patch-approval path containment (`..`, absolute, symlinked targets) for the medium predicate; `--turn-timeout` interrupt-then-continue and `--timeout` end-with-reason; `seq` monotonicity; a codex `steer`-with-no-active-turn rejection; registry pruning of the entry a resume needs.
- **minor — record fixtures before writing parsers.** The probe transcripts (claude init `system` message, interrupt exchange, `can_use_tool` round-trip, the app-server exchange above) are the only ground truth for every `[verify]` tag; persist them as repo fixtures and generate the fake `claude`/app-server scripts from them (design:717-718, 745-746), so the fakes can't drift from reality.
## 4. Scope
- **minor — the `--event-log` tee is broker-domain forensics.** Archiving is explicitly the broker's job (§5, design:657-665); a codemux-side crash-forensics tee duplicates it and adds a protected-state asset; recommend dropping it from the open questions and leaving any tee to the broker reading the event stream it already receives.
- No other misplacements found: the registry guard is correctly codemux's (only the spawner can enforce resume-time refusals), queueing/identity/frontends correctly stay with the broker, and `--turn-timeout`/`--shutdown-grace` correctly sit in codemux because only it holds the interrupt channel.
## 5. Three most important recommendations
1. Reorder and split the plan: scode stdio check as a step-0 gate, registry plus claude resume in one step so no commit ever carries a working unguarded `--resume`, and today's step 1 cut into three reviewed commits.
2. Fix the two over-claims Prompt B would implement literally — §4.7's codex parameter shape (bypass pair for every scode-wrapped session, mapping pair only unsandboxed-high) and §4.8's writable-set premise (codemux cannot enumerate scode's presets; placement excludes only read-only/medium children) — before any code is written.
3. Specify the session runner's contract with the repo's invariants up front: a per-session context with zero adapter state, mandatory reuse of `resolveTrustedCommand`/`buildExecutionEnv`/`sanitizeEnvironment`/`assertHarnessSupported`, no 16 MiB capture cap on the event stream, and fail-closed on unknown harness output for both adapters.
