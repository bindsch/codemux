# Panel review by claude

**Verdict: READY WITH CHANGES.** The protocol and the autonomy ceiling are sound. Four things in the design must change before Step 1: one rule cites a writable set that codemux does not have, the plan has no Antigravity adapter to build on, sessions need their own version floor, and the plan's order lets `--resume` ship before its guard does.

## 1. Defects in the design
- **blocker** — `docs/LIVE-SESSIONS-DESIGN.md:576-578`: Rule 2 relies on "the writable set codemux itself hands scode (it constructs that set, so it knows it)". That is false. `buildScodeCommand` (`src/sandbox.ts:26-63`) passes only `-C`, `--trust`, `--ro|--rw`, `--no-net` and `--scrub-env`. The writable roots are scode's preset, which codemux never sees. On macOS, whether `~/Library/Application Support` is writable under `standard` is unknown; on Linux, so is `~/.local/state`. **Fix:** at session start, run a free in-sandbox write probe against the registry directory and refuse with exit 64 if the write succeeds. Pin the probe with a sandbox-contract test on both platforms.
- **blocker** — `docs/LIVE-SESSIONS-DESIGN.md:182-193`, `:771-774`, `:966`: Antigravity is approved for v1, and the matrix says "scode yes (run path)". There is no agy adapter in `src/adapters/`, no entry in `src/harness-compatibility.ts`, no environment allowlist entry, and no ledger row. **Fix:** add a "Step 0b: agy run adapter". It goes through the full upgrade procedure (`docs/HARNESS-COMPATIBILITY.md` "Upgrade procedure"): autonomy mapping, project-safety checks, hermetic refused, installed-contract test. It must land before agy appears in any session step.
- **major** — `docs/LIVE-SESSIONS-DESIGN.md:363-370`, `:619-620`, `:632-636`; `src/harness-compatibility.ts:90-91`: The Claude Code floor is still 2.1.220, which allows pre-hardening builds (2.1.220–2.1.223). On those builds `--dangerously-skip-permissions` is honored, so high is a full bypass. The approved low→high resume is then an escalation: low gated each action through a human, and the bypass grants everything without asking. The same happens on any future build that decouples `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` from the hardening. **Fix (two parts):**
  - Give sessions their own floor at the first audited build with `--permission-prompts`, which also means `--permission-prompts host` cannot fail on an old binary.
  - In session mode, emit high as `default` mode plus the grant list, never `--dangerously-skip-permissions`. Then high's reach is set by codemux rather than by a harness side effect, and the approved ladder stays sound.
- **major** — `docs/LIVE-SESSIONS-DESIGN.md:236-240`, `:253-259`: "At read-only, any write or command execution stays denied whatever the caller answers" overstates what the ceiling covers. The session loads `--setting-sources user` (`src/adapters/claude.ts:163-167`). A user's `permissions.allow` rule, such as `Bash(git:*)`, runs without ever reaching the host channel. **Fix:** restate the ceiling as bounding the host channel only, with scode as the boundary. Alternatively, load no user settings in session mode below high.
- **major** — `docs/LIVE-SESSIONS-DESIGN.md:253-259`: "read-only — reads only" does not classify the real tool set: WebFetch, WebSearch, Task/Agent, Skill, SlashCommand, ExitPlanMode, TodoWrite, BashOutput/KillShell, and `mcp__*`. **Fix:** write the predicate as an explicit table of tool × level → allow-able. Every unknown tool is denied. A test diffs the table against the `tools` list in the init `system` message from a recorded fixture.
- **major** — `docs/LIVE-SESSIONS-DESIGN.md:126-127` vs `:493`: §3.2 sends a mid-turn user message through `thread/queue/*`, while §4.7 says `turn/start` is sent per user message. While a turn is active, the codex path has no defined behavior. **Fix:** pick one. I recommend a bounded codemux-side FIFO per session that issues `turn/start` on `turn/completed`; it avoids depending on the experimental queue API. Report it as `user_during_turn: "queue"`.
- **major** — `docs/LIVE-SESSIONS-DESIGN.md:331-332` vs `:748`: The design says a permission request stays pending "until answered or the session ends", yet Step 2 tests "approval timeouts". The design also never says what happens to a pending request on `interrupt`, on `--turn-timeout`, or on shutdown. **Fix:** in all three cases codemux answers the pending request with deny before acting. Late or duplicate `permission_decision` lines get `input_rejected` (`unknown_request`). Drop the timeout test, or define a timeout flag.
- **major** — `docs/LIVE-SESSIONS-DESIGN.md:190-191`, `:323-326`: The usage stream double-counts. Stream-json emits one `assistant` event per content block, and each one repeats the same `message.usage`. Codex app-server token counters may be cumulative per thread rather than per turn (`[verify]`). **Fix:** take turn usage from claude's `result` and codex's turn-completion usage only, dedupe per-message usage by `message.id`, and add a probe that settles codex cumulative vs per-turn.
- **major** — `docs/LIVE-SESSIONS-DESIGN.md:476-478`, `:498-504`: Only permission requests are specified. Other harness-initiated requests are not: claude `control_request` subtypes such as `hook_callback`, `mcp_message` and elicitation, and codex server→client requests such as `item/tool/requestUserInput`, auth-refresh requests, and MCP elicitation. Leaving them unanswered hangs the turn. **Fix:** answer every unrecognized request immediately with an error or deny response. Emit it as an `error` event carrying `raw`. Never treat it as approved.
- **major** — `docs/LIVE-SESSIONS-DESIGN.md:213-216`; `src/launch.ts:21-34`; `src/adapters/base.ts:39-51`: "Flags match `run`" does not say how the session reuses run's launch preparation. That preparation covers validation, `beforeLaunch`, `assertHarnessSupported`, `resolveTrustedCommand`, `assertNoProjectScodePolicy`, `assertNoCodexProjectExecutionConfig`, `buildExecutionEnv` and `prepareSandbox`. `RunRequest` also requires a `prompt` (`src/adapters/base.ts:297`). **Fix:**
  - Define a `SessionRequest` type.
  - Factor launch.ts's pre-spawn sequence into one shared function used by both paths.
  - Keep all live state in a launcher-owned `SessionContext`: child handle, FSM, pending-request map, registry entry.
  - Adapters get only pure methods: `buildSessionCommand(request, context)` and stateless parsers.
- **major** — `docs/LIVE-SESSIONS-DESIGN.md:597-603`, `:665`: Nothing stops two `codemux session --resume X` processes from running at once. Both harnesses would write one transcript, and the broker would receive two event streams under one id. **Fix:** the registry records a live owner (pid plus process start time). A resume of a live session is refused with exit 78 (`session_busy`).
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:398-401`: Claude's `-r/--resume` also takes a search term. A non-UUID value could select a different conversation. **Fix:** validate claude ids as UUIDs and codex thread ids against their pinned format. Refuse anything else with exit 64 before the value reaches argv.
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:690-691`, `:458-461`: A harness-level resume failure has no defined exit code. Rounds 10–17 show where stderr-phrase classification leads. **Fix:** exit 66 only from the registry lookup. Any harness-side resume failure is exit 1 with `raw` attached, and codemux never scans harness stderr text.
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:212-214`, `:311`; `src/process-runner.ts:13`: "`raw` is never truncated", but no per-line bound is set. A tool result carrying a whole file arrives as one line. **Fix:** set a per-line cap (16 MiB, matching `MAX_CAPTURE_BYTES`). Exceeding it, or invalid UTF-8, is a fatal `error`, so the stream is never cut silently.
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:212-214`: No backpressure is defined on codemux's stdout. A broker that stops reading grows codemux's memory without limit. **Fix:** bound the outbound queue. Overflow ends the session with a fatal `error`.
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:383-384`: The `author` deny-list misses NEL (U+0085), which is a Unicode line break. It also misses bidi overrides (U+202E), other C0/C1 controls, ESC and zero-width characters. "64 characters" does not say code units or code points. **Fix:** use an allowlist — reject Unicode categories Cc, Cf, Zl and Zp — and state the bound in code points.
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:514-515`: A Linux registry path that follows `$XDG_STATE_HOME` recreates round 19's finding 8: moving the variable hides the record while the transcripts stay put. **Fix:** derive the path from `HOME` alone, or record the resolved path in the error.
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:528-530`: Pruning can evict a live session, and a pid-only staleness check is fooled by pid reuse. **Fix:** never prune entries whose owner is live, and test lock staleness on pid plus process start time, not age alone.
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:632-633`: "the one downward move" is wrong. Low→medium, high→medium and others are also downward in the stated order. **Fix:** reword to "the one downward move this design calls out".
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:418-423`: Hermetic sessions for claude use a mechanism `codemux check --hermetic` never verified: stream-json input, persistence on, and `--safe-mode` across `--resume`. `src/adapters/base.ts:345-350` refuses unverified mechanisms. **Fix:** either the hermetic canary runs through the session path before the flag is accepted, or `--hermetic` is refused on sessions until it does.
## 2. Security
- **major** — The pre-hardening low→high escalation and the user allow rules that bypass the host channel (both in section 1).
- **major** — `docs/LIVE-SESSIONS-DESIGN.md:283-297`: The `updated_input` path check needs exact rules or it can be bypassed. **Fix:**
  - Name the argument key for each tool (`file_path`, `notebook_path`).
  - Resolve the deepest existing ancestor with realpath and normalize to NFC, matching `grantRule` (`src/claude-autonomy.ts:33-71`).
  - Deny any path that resolves outside the scope through a symlink.
  - Deny any `updated_input` that carries keys the tool's schema does not define.
- **major** — `docs/LIVE-SESSIONS-DESIGN.md:299-305`: Refusing answers that grant beyond the one request has to be a strict schema. Claude's `updatedPermissions` can target `userSettings` or `localSettings`, which persists a rule into every later run, not only this session. **Fix:** the outgoing `control_response` is built from scratch with `behavior`, `updatedInput` and `message`, and no caller field is copied through.
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:493-507`: The codex client must never send a caller-controlled `config` object, nor `fs/*`, `remoteControl/*`, `thread/realtime/*` or `turn/settings/update`. **Fix:** an allowlist of outgoing JSON-RPC methods, pinned by a grammar test.
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:490-507`: Run's codex hardening flags have no stated app-server equivalent: `--ignore-rules`, the hermetic and `--tools none` `--disable`/`-c` sets (`src/adapters/codex.ts:238-242`), and the effort override. **Fix:** list each one and its app-server carrier (root `-c`, or a JSON-RPC parameter), and add one probe that confirms the carrier is accepted.
## 3. The plan
- **major (order)** — `docs/LIVE-SESSIONS-DESIGN.md:416-417` vs `:725-729`: §4.5 says probe 6 (scode bidirectional stdio) runs "before anything else is built on it", but the plan runs every probe at the end of Step 1, after the parsers. **Fix:** add a Step 0 that runs probes 1–9 through `./bin/codemux` under scode, records sanitized fixtures, and amends §3 with the confirmed shapes. Only then build.
- **major (order)** — `docs/LIVE-SESSIONS-DESIGN.md:718-729` vs `:750`: `--resume` is reachable from Step 1, but the registry guards (hermetic match, containment, reach) arrive only in Step 3. **Fix:** keep `--resume` refused (exit 64) until Step 3 lands, or move the registry before codex.
- **major (size)** — `docs/LIVE-SESSIONS-DESIGN.md:698-729`: Step 1 is several thousand lines across at least six concerns and will not pass one five-auditor round. **Fix:** split it into these commits:
  - 1a: streaming process runner. Process group, graceful shutdown order (interrupt → turn end → close child stdin → grace → SIGTERM tree → SIGKILL), line framing, bounds, backpressure, all against a fake child. It must not use the immediate `process.exit(143)` handler in `src/process-runner.ts:359-366`.
  - 1b: protocol core. Framing, envelope, input validation, FSM.
  - 1c: the ceiling predicate as a pure, table-driven module.
  - 1d: claude session command builder and parsers, tested against the recorded fixtures.
  - 1e: CLI wiring and end-to-end tests against the fake harness.
- **minor (order)** — `docs/LIVE-SESSIONS-DESIGN.md:203-204` vs `:771`: Capability flags must appear on every `session_started` from Step 1, but capability reporting is scheduled for Step 4. **Fix:** emit capabilities from Step 1 and keep only the per-adapter matrix test in Step 4.

## 4. Scope
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:378-382`: The `[author]` prefix belongs in the broker. Codemux should carry `author` as a data field only. The broker owns presentation and can prefix the text itself, which removes `--no-author-prefix` and the transcript-forgery discussion from codemux.
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:427-429`: `--turn-timeout` belongs in the broker. The design already treats the idle timeout as broker policy, and the broker can send `interrupt` itself. Keep `--timeout` and `--shutdown-grace` in codemux, because they still apply when the broker is dead.
- **minor** — `docs/LIVE-SESSIONS-DESIGN.md:657-665`: Placement is otherwise right. The registry, the ceiling, usage normalization and the stdin-EOF shutdown belong in codemux; queueing across users, archiving, the event log, identity and attach belong in the broker.
## 5. Three most important recommendations
1. Add a Step 0 that runs every live probe, including scode bidirectional stdio and the registry write probe, records the fixtures, and corrects §3 and §4.8 rule 2 before any parser or guard is written.
2. Give sessions their own Claude Code floor at the first audited `--permission-prompts` build, and emit session high as `default` mode plus the grant list without `--dangerously-skip-permissions`, so the approved low→high resume never widens reach.
3. Factor launch.ts's pre-spawn sequence into one function shared by `run` and `session`, keep all live state in a launcher-owned `SessionContext`, and add a parity test that the session child's argv prefix and environment match run's for the same request.
